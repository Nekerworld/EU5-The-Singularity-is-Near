# 모드 상시 로그 (자동 기록)

게임을 켜고 플레이하면 모드가 스스로 `logs/debug.log`에 `TSIN_LOG;...` 줄을 남긴다. 게임 규칙을 켤 필요가 없다. 에이전트가 게임을 실행할 수 없으므로, 사용자가 이 로그를 넘기면 `tools/read_log.py`가 읽기 쉬운 보고서로 바꾼다. 모든 항목은 **사용자 확인 필요**(게임 안에서 실제로 기록되는지는 아직 보지 못했다).

## 사용 순서
1. 게임을 켠다(새 게임 또는 세이브 이어하기). 로비가 끝나고 지도가 보이면 **그 자리에서** 세션 점검이 한 번 남는다. 한 달을 기다릴 필요 없다.
2. (선택) 더 오래 플레이하면 매달 같은 점검이 다시 남는다. 조사 버튼·국가 비교·상장 등은 쓸 때마다 훅이 추가된다.
3. 게임을 끄고 `Documents/Paradox Interactive/Europa Universalis V/logs/debug.log`와 `error.log`를 에이전트에게 준다(다른 곳에 복사했다면 `--debug`, `--error`로 경로 지정).
4. `python tools/read_log.py` 실행. 보고서는 화면과 `tools/out/mod_log_report.md`에 나온다.

debug.log는 게임을 실행할 때마다 새로 만들어지므로 파일 하나가 플레이 한 번이다. **한 번만 켜고 바로 꺼도** `hook=session_start`와 전체 `chk`/`snap`/`fmt`가 있어야 한다(**사용자 확인 필요**: `on_game_started_after_lobby`가 이어하기에서도 도는지).

## 로그 줄 4종 (`TSIN_LOG;k=...`)
| 종류 | 언제 | 내용 |
|---|---|---|
| `hb` | 세션 시작 + 매달 | 점검 묶음의 시작. `schema` 번호(현재 2) |
| `chk` | 세션 시작 + 매달, 점검마다 한 줄 | `id=항목;v=0/1`. V/P/H·도시권·언론 등 상태 포함. 고정 문구 |
| `hook` | 세션 시작(`session_start`) 또는 기능 실행 시 | 조사·비교·상장 훅. `session_start`는 로비 직후 자동 |
| `snap` | 세션 시작 + 매달 | 날짜, 나라, GDP, 운동·언론 단계, 도시권, 군수/연료/공군 비축 등 |
| `fmt` | 세션 시작 + 매달 | 숫자 읽기 방식 진단용(아래) |

점검 항목과 훅의 전체 목록과 설명은 `tools/gen_mod_log.py`의 `CHECKS`, `HOOKS`에 있다. 읽기 도구도 같은 표를 쓴다.

## 왜 숫자를 전역 변수로 옮겨 쓰는가
기존 `TSIN_OBS`, `TSIN_ECON` 줄은 실제 로그에서 값이 모두 비어 있었다. 로그가 `Promote 'ROOT' returned nullptr`를 남겼다. `debug_log`의 문구는 ROOT 없이 번역되기 때문이다. 그래서 새 로그는 두 가지로 나눈다.
- 참/거짓 사실은 고정 문구 한 줄(`chk`, `hook`). 값 읽기가 필요 없어 항상 나온다.
- 숫자는 먼저 전역 변수로 복사하고 `[GetGlobalVariable('tsin_log_gdp').GetValue|0]`로 읽는다(바닐라 GUI가 쓰는 전역 함수). 이것이 로그에서도 되는지는 **사용자 확인 필요**다.

`fmt` 줄은 같은 값을 `GetGlobalVariable`, `ROOT`, `THIS`, `SCOPE`, `GetPlayer` 다섯 방식으로 찍어 어느 것이 되는지 알려 준다. 보고서 2절이 이 결과와, 전역 방식이 실패했을 때 바꿀 방식을 알려 준다. 전역 방식이 실패해도 `chk`와 `hook` 판정은 그대로 쓸 수 있다.

## 판정 규칙 (보고서 1절)
- **FAIL**: 훅 직후의 점검이 기대와 다르다(예: 국내 조사를 실행했는데 보고서 변수가 없다), 쿨다운 거부 훅이 나왔다, 거래소 표식이 있는데 개설 조건이 거짓이다, 로그가 한 줄도 없다.
- **WARN**: 제7시대인데 GDP 장부가 1년 넘게 없다, 로그 문구의 값 읽기가 실패했다.
- **PASS**: 기능을 실행했고 다음 점검에서 결과가 확인됐다.
- **미검증**: 기능을 아직 쓰지 않았거나 다음 월간 점검이 아직 없다. 통과로 세지 않는다.
- **정보**: 한 번도 참이 아니었던 점검(기능이 아직 열리지 않은 것일 수 있다).

보고서의 나머지: 3절 기능 사용 횟수, 4절 점검 변화 시점, 5절 스냅샷 표(`--rows`, `--all`), 6절 이 모드의 다른 `debug_log` 줄(옛 `TSIN_OBS`/`TSIN_ECON`은 값이 비어 있다), 7절 `error.log`의 이 모드 관련 오류(분류와 횟수, 위치).

## 새 항목 추가 방법
`tools/gen_mod_log.py`의 표에 한 줄을 넣고 `python tools/gen_mod_log.py`를 실행한다(효과, 현지화 영문·한글, 보고서가 함께 바뀐다). 새 훅은 해당 효과에 `debug_log = tsin_log_hook_<id>`를 넣는다. `tools/tests/test_mod_log.py`가 선언과 사용의 불일치를 잡는다.

## 한계
- 모든 줄은 플레이어 나라 한 곳의 상태다. AI 나라 상태는 기록하지 않는다(기업 상장 훅은 AI 상장도 센다).
- 훅 직후 기대 상태(조사 보고서 등)는 다음 점검(`session_start` 직후 묶음 또는 다음 달)에서 확정된다. 세션만 열고 끈 경우에는 상태 점검만 남고, 클릭 훅은 해당 기능을 써야 한다.
- 게임 실행 중 모드가 스스로 틀렸다고 알려 주지는 않는다. 보고서의 판정은 위 규칙으로 로그를 읽은 결과일 뿐이다.
