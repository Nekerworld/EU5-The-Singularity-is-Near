# TSIN operational situation button

The existing TSIN management and shortcut buttons remain. A new Current Situation button beside them opens an independent movable warning list. Its badge counts active, non-hidden warning types; it does not count every affected building/unit or unread messages. The main management window and situation/disaster ribbons are not replaced or muted.

The warning types cover strategic-goods prices, missing building inputs, electricity imbalance, unprofitable buildings, hiring, industrial market access, army food, reinforcement reserves, reduced maintenance, naval attrition, provincial/market food, crowding, education decline pressure, recurrent subsidized losses, deficits/loans and stock-index falls. No disaster/situation-active predicates or opportunity notifications are registered here.

Native alerts cannot be read inside scripted_gui `is_valid` (the engine forbids `is_alert_triggered` in interface triggers). A monthly player-only effect samples those native alerts into country caches (`tsin_ops_alert_*`). UI predicates and the badge read only those caches plus the dated detailed snapshot. Native actions are opened through known economy, production and unit-overview interfaces. No army automation, trade order, policy or subsidy is executed by inspecting a warning.

Detailed checks run only for human countries, once per three months. Opening the list seeds the first scan if needed. Manual refresh is limited to once per game day. The scan makes one owned-location/building pass, deduplicates each local market with a temporary scope list, checks ten configured strategic goods once per market and clears the list afterward. No world scan or hover-time production aggregation is added.

Each high-price item can open the stored highest-price market, provided the market still exists. Prices compare against the configured reference price, with positive demand in a market containing owned territory. This is a shared-market observation, not proof of domestic industrial consumption or actual shortage. Electricity compares market supply with demand; inventory/trade may soften the immediate effect. Warning details explicitly distinguish these meanings.

Initial reference prices match installed vanilla/TSIN definitions: coal 2, iron 3, copper 3, steel 5, tools 3, engines 6, fertilizer 2.5, explosives 5, oil 4, rubber 4. They are configurable; an external mod changing reference prices requires updating this registry. High-price threshold is 150%, electricity supply floor 90%, worker-capacity floor 50%, industrial access floor 75%, crowding warning 90%. These are diagnostic defaults, not changes to gameplay mechanics.

Subsidy warnings identify subsidized negative-profit buildings in successive detailed samples. Building losses are NOT presented as the national subsidy expenditure. Deficit/subsidy persistence advances at most once per scan interval, independently of manual refreshes. A resolved condition clears its streak immediately at the next check. Consecutive samples do not prove every intervening day was negative. Reinforcement warnings identify manpower under 10% of maximum with an army present, not a measured stop in individual-unit reinforcement. Education pressure requires a cached target below current coverage while the literacy/lower-education cap is not binding; it advises reviewing both facilities and policy. Stock decline uses the existing four-sample minimum and 60%-of-recent-mean comparison.

Each warning card has an explicit Hide button that suppresses that type for the current application session. Restore Hidden Types clears only these UI preferences. A zero badge means no enabled warning currently qualifies; it does not certify every economic or military system is healthy. The footer distinguishes monthly-cached native alerts and the dated detailed snapshot.

Edit ui/operational_alerts.json, then run tools/gen_operational_alerts.py and tools/gen_dashboard.py. Both provide --check modes and are checked by the standard integration validator. Future-era warning rules can be registered without changing the dashboard tab structure. Keep UI predicates cheap, never put `is_alert_triggered` in rule conditions, and do not add disaster/situation predicates here.

In-game verification after restarting: TSIN button unchanged; neighboring button opens/closes; badge matches visible rule rows; native input/food/maintenance states resolve after the monthly cache; refresh updates the dated cache; changing a market price produces the correct reference ratio; Hide suppresses only that type; restoration works; ribbons retain existing behavior. Static validation cannot prove native trigger/glue behavior or runtime scan cost. Detailed filters and thresholds require play testing.
