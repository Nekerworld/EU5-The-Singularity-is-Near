# The Singularity is Near — 미래 개발계획과 구현 현황

작성일: 2026-11-15
검토 기준: `51361f7` — 전 시대 기업·조건부 금융위기·독립 TSIN 창 등록까지 구현된 상태

계획 추가: 2026-11-15, 문서 커밋 `e75f15b` 이후 논의한 역사 사건·럭키네이션·국경 정리와 Historical Expansion AI 설치본 0.3.5 분석을 제20~23절에 반영. 이번 갱신은 문서 작업이며 해당 기능을 TSIN에 구현한 것은 아니다.

현재 실행 상태(2026-11-15): [단계별 실행 기록](implementation_sequence_2026_11_15.md)을 기준으로 P1 금융 UI, P2 수동 역사/국경 진단, P3 러시아 럭키네이션 시제품, P4 역사 사건 첫 제작분 24개를 코드로 구현했다. 정적 검증과 인게임 완료는 구분한다. 아래의 나머지 금융·통화·거래·후속 시대 제안은 여전히 미구현이며 전선 자동전투는 보류한다.

## 1. 문서의 목적과 상태 구분

지금까지 논의한 아이디어 중 아직 구현하지 않은 기능을 정리한다. 다른 에이전트가 기존 기능을 중복 구현하거나 이전 구상으로 되돌리지 않도록 현재 코드와 후속 계획을 구분한다. 이 문서는 계획 산출물이며, 모든 제안의 즉시 구현을 승인하는 지시서는 아니다.

| 상태 | 의미 |
|---|---|
| 구현됨 | 코드가 존재한다. 인게임 검증 완료를 뜻하지 않는다. |
| 부분 구현 | 단계별 코드가 추가되었고 나머지 범위·인게임 검증이 남았다. |
| 미구현·방향 합의 | 사용자 요청에서 배치나 목표를 정했지만 아직 코드에 반영하지 않았다. |
| 미구현·설계 제안 | 구체화한 후보이며 수치·방식은 후속 검토 대상이다. |
| 실현성 검증 | 엔진에서 필요한 기능을 사용할 수 있는지 먼저 실험해야 한다. |
| 대체됨 | 최신 구상으로 교체한 이전 제안이다. 그대로 구현하지 않는다. |

최신 방향은 **전역 공용 체계 → 시대별 콘텐츠**다. 금융 UI는 **F2 경제 패널 안에 금융 상위 탭을 두고, 그 아래에 하위 탭을 배치**한다. F3 독립 금융 패널을 만들고 기존 F3~F9를 F4~F10으로 미는 안은 대체되었다.

## 3. 공용 금융 UI 재구성

### 3.1 목표 화면 — 부분 구현

| 경제 상위 탭 | 하위 구성 |
|---|---|
| 수지 | 기존 국가 수입·지출·재정 이력 |
| 금융 | 현황·증시·신용·통화·외환·연금 |
| 시장 | 기존 시장 화면 |
| 관세 | 기존 관세 화면 |
| 교역 | 기존 교역 화면 |

기존 상위의 신용·주식은 금융 아래로 옮긴다. 금융을 선택한 때에만 두 번째 탭 줄을 표시한다. F1~F9와 좌측 대분류 버튼 순서는 유지한다.

하위 탭은 짧은 명칭과 아이콘을 사용하고 호버에 전체 이름을 표시한다. 긴 이름 6개를 한 줄에 억지로 넣지 않는다. 세부 항목을 선택했을 때만 상세 장부와 조작을 펼쳐 패널을 과밀하게 만들지 않는다.

### 3.2 탭별 역할

| 하위 탭 | 상단 | 본문과 조작 | 최초 도입 범위 |
|---|---|---|---|
| 현황 | 금융 건전성·최근 추세 | 위험 원인, 사건 기록, 관련 탭 이동 | 기존 기업·부채·위기 지표부터 |
| 증시 | 주가 지수·기업 요약 | 기업 목록, 설립·확장·본사·특허장 | 현재 기능 이전 |
| 신용 | 부채·이자·상환 부담 | 바닐라 대출·상환·채권·파산 | 기존 엔진 기능 보존 |
| 통화 | 통화제도·금리·물가 | 발권·긴축·태환·화폐개혁 | 통화 모형 구현 후 |
| 외환 | 환율·준비자산·대외 위험 | 외채·자본 이동·환율 방어·통화 협정 | 외환 모형 구현 후 |
| 연금 | 납입·급여·기금 건전성 | 운용 비중·지원·보험 제도 | 실제 기금 구현 후 |

P1에서 현황·증시·신용을 코드로 연결했다. F2 단축키·경제 패널 제목은 유지하고 기존 `credit` 컨트롤러를 금융 본체로 사용한다. 실제 인게임 전환은 확인 대기다. 미구현 탭을 작동하는 것처럼 표시하지 않는다. 해금 여부를 설명할 필요가 없다면 구현 전에는 탭을 숨긴다.

### 3.3 구현 방식과 실현성 확인

- 바닐라 F1의 `header_secondary_tabs`와 `button_secondary_tab_alt`를 재사용한다.
- `GovernmentView.SetLowerTabToEstates` 같은 전용 엔진 메서드를 금융용으로 임의 생성하지 않는다. 금융 선택 상태는 공용 UI 변수나 검증된 화면 매개변수로 관리한다.
- 기존 `credit` 화면을 금융 상위 탭의 본체로 확장하는 안이 우선 검토 대상이다. `CreditLateralView`의 대출·채권·파산 데이터 연결을 유지할 수 있기 때문이다.
- 신용 선택 때 기존 본문을, 증시 선택 때 공용 주식 패널을 표시한다. 기존 수지 본문에 금융 기능 전부를 쌓지 않는다.
- P1에서 기존 credit 컨트롤러를 보존하는 시제품을 구현했다. 원본 본문·조작의 보존을 회귀 검사했고 실제 탭 전환·배치·조작은 인게임 검증 대기다.
- 별도 네이티브 `finance_group` 등록이나 F3 신설을 전제하지 않는다.

### 3.4 놓치면 안 되는 연결

1. 부채·파산·차환 알림은 금융의 신용 화면으로 이동한다.
2. 기존 주식 바로가기와 운영 경고는 금융의 증시 또는 해당 위험 화면으로 이동한다.
3. 매개변수 없는 기존 `credit` 호출은 원래 의도인 신용 화면을 연다.
4. 상위 금융 탭은 어느 금융 하위 화면을 보고 있어도 선택 상태를 유지한다.
5. 수지·시장·관세·교역에서 두 번째 금융 탭 줄이 남지 않는다.
6. 탭 클릭이나 호버가 주가 갱신·위기 누적·민간 진입을 추가 진행시키지 않는다.
7. 기본 UI와 Glorp 모두 같은 하위 콘텐츠를 사용한다.

참고: [stock_market_ui.md](stock_market_ui.md), [dashboard_framework.md](dashboard_framework.md), [gen_stock_market_ui.py](../tools/gen_stock_market_ui.py), [capital_market_ui.py](../tools/capital_market_ui.py).

## 4. 금융 현황과 위험 설명 — 미구현·설계 제안

금융 건전성을 단일 점수로만 표시하지 않고 원인을 분리한다.

| 위험 | 보여줄 정보 | 가능한 대응 |
|---|---|---|
| 유동성 | 단기 지급 요구·현금·만기 예정액 | 긴급 유동성·지급 유예·단기 차입 |
| 지급 능력 | 자본·부실채권·누적 손실·이자 부담 | 자본 확충·채무 조정·정리 |
| 과열 | 기업 가치·영업 기반·신규 투자·진입 추세 | 대출 규제·공시·금리·시장 정리 |
| 집중 | 특정 산업·은행·외국에 대한 노출 | 분산·익스포저 제한 |
| 대외 | 외화 부채·준비자산·환율 압력 | 차환·준비자산 사용·평가절하 |

경고에는 현재 값, 임계치, 관측 기간, 직전 변화와 원인을 표시한다. 숫자를 설명하지 못하는 종합점수만 추가하지 않는다.

금리 변경·증자·정리·태환 중단 등 주요 금융 사건을 기록한다. 시간 순서로 일어났다는 사실과 모형에서 직접 적용한 효과를 구분해, 근거 없는 인과관계를 표시하지 않는다. 기록 개수는 제한한다.

## 5. 기업의 자금조달과 장부 — 미구현·설계 제안

현재 기업 수·주가·본사·영업 기반의 모형을 확장한다. 기존 기업을 삭제하거나 20개 유형을 새 ID로 다시 만들지 않는다.

### 5.1 추가할 장부

- 기업군별 현금·이익·유보금·채무·이자 부담·부실 상태.
- 투자에 사용한 자금과 실제 회수된 수익.
- 지분·배당을 도입할 경우 소유 주체와 배당을 받을 장부.
- 기존 `tsin_stock_*`는 기준 100의 평가 지수다. 지수 × 건물 레벨인 현재 가치 추정치를 현금 수익으로 바로 지급하지 않는다.
- 실제 법인의 건물 소유권을 엔진에서 분리할 수 있는지는 별도 확인한다. 최초 범위는 국가·업종 단위 합산 모형이다.

### 5.2 콘텐츠

| 기능 | 선택과 결과 | 구현 전 필요한 것 |
|---|---|---|
| 배당·유보 | 소유자에게 배분하거나 투자 재원으로 보유 | 이익 단위와 지급 대상 정의 |
| 증자 | 자금 유입, 기존 지분 희석 | 출자자의 지출과 지분 장부 |
| 회사채 | 지분 희석 없이 조달, 이자·만기 증가 | 채권자·채무자·상환 책임 |
| 투자 붐 | 기대 수익 높은 업종으로 자금 이동 | 자금 출처·투자 대상·회수 규칙 |
| 구조조정 | 손실 인식·채무 조정·합병·기업 정리 | 손실 부담 주체와 기존 ID 보존 |
| 공시·회계 규제 | 투명성과 운영 비용, 정보 위험 변화 | 정책과 위험 모형 |

자유방임에서 플레이어가 모든 민간 기업의 배당·투자처를 직접 지정하는 구조는 피한다. 정부는 과세·공시·금융 규제·공적 지원 조건을 정하고 민간 행동은 그 안에서 자동 결정한다.

현재 시민 자금으로 기업이 진입하는 효과와 새로운 출자·은행 장부가 같은 돈을 두 번 차감하거나 같은 투자로 보너스를 중복 지급하지 않도록 이행한다.

## 6. 은행과 신용 — 미구현·설계 제안

### 6.1 은행 부문

최초에는 국가별 합산 은행 부문을 사용한다. 은행 수백 개나 팝별 예금 계좌를 기본 구현으로 삼지 않는다.

| 조달·자본 | 운용 자산 | 위험 |
|---|---|---|
| 예금·투자자 자본·중앙은행 차입 | 준비금·기업 대출·국채 | 부실채권·인출 압력·산업 편중·자본 부족 |

국가가 정할 수 있는 정책 후보는 준비금 규제, 대출 규제, 예금보험, 공적 지원, 부실 은행 정리 방식이다. 예금 인출 사태는 자금 부족이나 신뢰 저하 등 근거가 있을 때 발생하도록 설계한다.

**유동성 부족과 지급 불능을 구분한다.** 일시적 현금 부족에는 담보·금리·만기가 있는 긴급 대출을, 누적 손실에는 자본 확충이나 구조조정을 요구한다. 같은 무료 구제 버튼으로 모든 위기를 해결하지 않는다.

### 6.2 국채와 국가 신용

| 기능 | 목표 | 엔진 확인 사항 |
|---|---|---|
| 이자 부담·차환 예정 | 국가 재정의 위험을 설명 | 기존 대출 정보에서 읽을 수 있는 필드 |
| 단기·장기 조달 | 차환 위험과 금리 고정의 선택 | 원래 계약의 만기·조건 변경 가능 여부 |
| 국내·해외 조달 | 국내 자금 흡수와 대외 의존의 차이 | 채권자·채무 통화 구분 가능 여부 |
| 신용 위험 | 재정 추세·부채·채무 이력을 반영 | 별도 지표를 native 차입 비용에 연결하는 방법 |
| 채무 재조정 | 만기 연장·이자 조정·손실 분담 | 기존 계약을 안전하게 변경할 수 있는지 |
| 긴급 차입 | 전쟁·기근·금융위기의 비용 있는 대응 | 기존 차입과 별도 장부의 중복 여부 |

바닐라 대출을 유지한 요약·위험 표시를 먼저 구현한다. 실제 다중통화 채권과 만기 계약은 필요한 API를 확인한 뒤 도입한다. native 자동 이자와 모드 장부가 같은 이자를 두 번 청구해서는 안 된다.

## 7. 국가별 통화와 통화정책 — 미구현·설계 제안

### 7.1 권장 구조와 한계

두캇을 내부 기준 단위로 유지하고 그 위에 통화 계층을 추가하는 안이 우선 후보다. 이는 권장안이며 엔진 전체 회계를 교체하는 방안이 확정된 것은 아니다.

| 계층 | 정의 |
|---|---|
| native 회계 | 기존 국고·상품 가격·거래·팝/계층 자산·대출의 기준 단위 |
| 통화 모형 | 통화 ID, 환율, 제도, 준비자산, 신뢰도, 정책금리 |
| 사용자 표시 | 자국 통화 금액과 필요한 경우 기준 단위 병기 |

통화는 발행 주체별로 관리하고 통화동맹은 여러 국가가 같은 ID를 사용하도록 한다. 국가 태그 변경·통일·분열·종속·국가 소멸 시 통화와 부채가 어떻게 이어질지 정한다.

환율을 `E_A = 기준 두캇 1당 A 통화 수`로 정의한다면:

- 표시액: `A 통화 금액 = 기준 금액 × E_A`.
- 교차 환율: `A 통화 1당 B 통화 = E_B / E_A`.
- 단위 변경이나 액면 개혁만으로 내부 국고·실질 자산이 증가해서는 안 된다.
- 기준 100의 주가 지수, 비율, 성장률은 화폐 금액처럼 환산하지 않는다.
- GDP와 같은 기간 흐름, 자산과 같은 잔액, 지수의 단위를 문서와 툴팁에 구분한다.

환율 변수만 바꿔서는 바닐라 무역 AI·상품 수요·결제 금액이 자동 연동되지 않는다. 초기 기능은 금융·통화 모형과 효과 연결의 근사 구현이다. 모든 native 거래·임금·팝 저축·계약을 실제 다중통화로 바꾸는 작업은 별도 실현성 검증 대상이다.

### 7.2 제도별 콘텐츠

| 제도/기능 | 필요한 상태 | 플레이어의 선택 |
|---|---|---|
| 금속화폐·복본위 | 주화·신뢰도·물가의 근사 | 주조·화폐 정비·제도 전환 |
| 금본위 | 고정 태환 비율·금 준비자산·태환 부담 | 준비금 확보·금리 대응·태환 유지/중단 |
| 고정환율 | 목표 환율·외환보유액·방어 비용 | 환율 방어·평가절하·제도 변경 |
| 변동환율 | 물가·금리·신용·대외 압력 | 금리·개입·자본 이동 정책 |
| 화폐개혁 | 구/신 통화 비율·계약 처리 | 액면 정리·통화 통합·신뢰 회복 |

금 생산 재화, 두캇 국고, 중앙은행 금 준비자산을 같은 값으로 취급하지 않는다. 준비자산 매입·매각의 대가와 장부상 위치를 명시한다. 기존 금본위 정책 보정과 새 모형의 효과가 중복되는지도 검토한다.

### 7.3 중앙은행과 금리

- 정책금리, 국가 차입금리, 기업 차입금리, 예금 수익률을 구분한다.
- 정책금리는 기준이고 신용·만기·위험 가산이 실제 차입 비용을 바꾸도록 설계한다.
- 발권·긴축, 중앙은행 국채 매입, 최종대부자, 태환 중단을 후보로 둔다.
- 금리 변경에는 갱신 주기·변경 폭·쿨다운과 AI 정책을 함께 설계한다.
- 초기 시대부터 현대 중앙은행의 모든 기능을 제공하지 않는다. 제도·발전·국가 조건으로 기능을 해금한다.
- 긴급 유동성과 재정 지원은 비용·담보·만기·손실 부담을 가진다. 무료 국고 생성 수단으로 만들지 않는다.
- 통화 신뢰도는 정책의 결과를 설명하는 지표로 설계하며, 무작위 페널티만 반복하는 수치로 사용하지 않는다.

## 8. 외환·해외 투자·외채 — 미구현·설계 제안

| 콘텐츠 | 구체화할 것 |
|---|---|
| 외화 부채 | 계약 통화·원금·만기·환율 변화에 따른 상환 부담 |
| 해외 투자 | 출자 주체·대상·수익·손실·회수 |
| 자본 유입/이탈 | 수익 기대·신뢰도·금리·위험과 연결 |
| 자본 통제 | 유출 완화와 신규 유입 둔화의 비용 |
| 준비자산 개입 | 방어에 사용한 자산·잔액·환율 효과 |
| 통화 협정 | 고정환율·통화동맹·긴급 준비자산 지원 |

위기 경로 후보는 `외채 의존 → 자금 이탈 → 준비금 감소 → 금리 인상/평가절하/채무 조정`이다. 자국 통화 부채와 외화 부채를 같은 규칙으로 평가절하하지 않는다.

실제 국제수지를 모두 읽거나 결제 통화를 바꿀 수 있다고 가정하지 않는다. 초기에는 사용 가능한 집계값으로 근사하고, 외국 자산의 차감·귀속·회수와 국가 소멸 시 처리를 먼저 정한다.

## 9. 연금·보험 — 미구현·설계 제안

### 9.1 연금

현재 사회보험 정책과 실제 기금 장부를 구분한다. 후속 모형에는 납입액·급여·적립금·운용 수익·적립 부족·국고 지원을 둔다.

- 적립식과 당해 납입으로 급여를 지급하는 방식은 별도 제도 후보로 검토한다.
- 기금 운용은 국채·주식·현금 등 소수의 합산 비중으로 관리한다.
- 적립 부족 시 납입 조정·급여 조정·지원·제도 개편의 선택을 제공한다.
- 수급 인구를 엔진에서 직접 읽을 수 있는지 확인한다. 사용할 수 없다면 추정치를 표시하고 실제 개인별 연금으로 설명하지 않는다.
- 최초 구현에서 모든 팝의 개인 계좌를 순회하지 않는다.

### 9.2 보험

| 종류 | 연결할 손실 |
|---|---|
| 해상보험 | 해적·봉쇄·교역 관련 손실 |
| 산업보험 | 산업 사고·재해 |
| 예금보험 | 은행 정리·예금 손실 |

보험료·적립금·보장 범위·자기부담·지급 상한을 정의한다. 기존 사건의 배상과 보험 지급을 중복 적용하지 않는다. 보험 자산보다 손실이 클 때는 지급 제한·정리·공적 지원 등 결과가 있어야 한다.

## 10. 금융위기 확장 — 부분 구현 위의 후속 계획

### 10.1 현재 기준을 보존

- 과잉 진입 3차례 또는 심한 과잉공급 4차례의 분기 관측에 근거한 국지 위기가 이미 있다.
- 1900년 이후 다국가·다시장 실물 스트레스에 근거한 세계 대공황도 이미 있다.
- 현재 국지·세계 위기의 재발 대기시간은 각각 10년·25년이다. 상세 임계치는 코드와 [capital_markets.md](capital_markets.md)를 읽는다.
- 기존 19세기 대불황과 세계 대공황의 중복 시작 방지를 유지한다.
- 단순 주가 등락이나 정해진 연도만으로 재앙을 추가하지 않는다.

### 10.2 추가할 전파와 회복

1. 은행 부실이 대출 축소·투자 위축으로 전해지는 경로.
2. 예금 인출과 은행 유동성 위기.
3. 외채·자본 유출·준비금 고갈에 따른 통화 위기.
4. 채권 손실과 국가 신용 위기의 상호 작용.
5. 중앙은행 지원·은행 정리·채무 조정·재정 대응에 따른 회복 경로.
6. 위기의 지속 조건·종료 조건·모든 임시 효과의 정리.

현재 수도 시장 표본을 전국 시장 전수조사로 조용히 확대하지 않는다. 더 넓은 표본이 필요하면 범위와 비용을 명시하고 측정한다. 사건 발생 확률, 위험 관측, 실제 붕괴 판정을 구분한다.

정치 연결용 `tsin_financial_radicalization` 표식은 이미 있다. 후속 이념 모형이 금융위기와 기존 정치·사회 상태를 함께 읽도록 확장한다. 불황 하나만으로 파시즘이나 특정 정권이 자동 성립하게 하지 않는다.

## 11. 금융 외 경제의 확장 아이디어

빅토리아 스타일의 생산·투자·고용 연결을 장기 방향으로 유지한다. 현재 EU5의 건물·재화·팝·시장 체계를 이어 쓰며 다른 게임의 경제 엔진이 구현되어 있다고 설명하지 않는다.

| 아이디어 | 현재 기반 | 미구현 범위 |
|---|---|---|
| 실물 투자와 기업 자금 연결 | 산업 건물·민간 기업 수·시민 자금 | 실제 설비 투자·조달·회수 장부 |
| 수익성과 고용의 설명 | 고용·입력 부족·건물 이익 경고 | 투자·축소·정리의 통합 의사결정과 설명 |
| 명목·실질 경제 지표 | 추정 GDP·성장률 | 물가 기준과 불변가격 지표, 일관된 단위 |
| 경기 순환 | 상품 과잉공급·주가·조건부 위기 | 신용·투자·생산·고용이 연결된 순환 |
| 시대별 생산 고도화 | 7시대 기술 단계형 생산 방식 | 후속 시대 상품·설비·수요·해금 |
| 전시 경제 | 기존 군수품·부대 물자 | 민수/군수 자원 배분·동원과 전후 전환 |

이미 구현된 철도·전력·농업 기계화·자동화 업그레이드는 재사용한다. 경제 통계의 외부 로그 문제와 기존 UI 연결 확인은 새 경제 콘텐츠가 아닌 별도 검증/수정 항목으로 다룬다.

## 12. 후속 시대 콘텐츠

### 12.1 공통 규칙

현재 연표의 원본은 [data/eras.json](../data/eras.json)이다. 각 시대는 바닐라와 같이 **제도 3종을 수용해 관련 발전 분야를 여는 구조**로 설계한다. 8~12시대의 제도 이름·ID·구체 효과는 아직 확정하지 않았다. 아래 주제는 콘텐츠 후보이며 실제 해금 정의가 아니다.

| 시대 | 기간 | 현재 상태 | 후속 콘텐츠 방향 |
|---|---|---|---|
| VII 산업 | 1837–1900 | 콘텐츠 구현·검증 중 | 금융 공용 기능과의 연결, 안정성·장기 밸런스 |
| VIII 대전 | 1900–1945 | 시대 뼈대 | 대량생산·내연기관·기계화·대중정치·총력전 |
| IX 원자력 | 1945–1990 | 시대 뼈대 | 원자력·핵 억지·국제 질서·대량소비 |
| X 정보화 | 1990–2035 | 시대 뼈대 | 디지털 통신·세계 공급망·지식경제 |
| XI 인공지능 | 2035–2120 | 시대 뼈대 | 지능형 자동화·노동 전환·통치와 사회 제도 |
| XII 우주 개척 | 2120–종료일 | 시대 뼈대 | 지외 정착·우주 산업·성간문명으로의 확장 |

2200년은 장기적인 성간문명 목표 시점이며 게임 종료일이 아니다. 현재 종료일 `2337.12.31`은 유지한다. 시기별 동적 전환을 도입할지는 별도 결정 대상이며 현재 등록된 연도만으로 구현 완료를 판단하지 않는다.

### 12.2 제8시대의 우선 콘텐츠

- 기존 노동 불만·사회주의 세포·교육·운동·기업·GDP 상태를 이어받는 대중정치와 이념 갈등.
- 파시즘·공산주의·민족주의 대중 운동, 정당·정부 전환·총파업·혁명 관련 콘텐츠 후보.
- 금융위기와 정치 급진화의 연결. 세계 대공황의 기본 판정은 재구현하지 않는다.
- 총력동원·민수/군수 전환·철도 및 기계화 보급.
- 자동차·항공·노급 전함 등 기존 7시대 말기 군사·산업 사슬의 후속 콘텐츠.
- 국제연맹형 국제기구와 전후 질서 관련 후보.
- 기존 질소 고정·암모니아 합성·집약 농업 후반 기술을 8시대로 옮길지 검토. 이미 연구한 세이브와 선행 참조를 보존할 이행안 없이는 이동하지 않는다.

이념을 종교처럼 표현하는 방식은 이전 참고안 중 하나다. 종교 데이터베이스를 그대로 덮어쓰는 방식으로 확정된 것이 아니다. 태그와 무관한 범용 정치 기제를 우선하고, 역사적 고유 기업과 기존 사건 연결의 예외는 보존한다.

참고: [age8_handoff.md](age8_handoff.md). 해당 문서의 ‘대공황 미구현’ 등 오래된 표현은 현재 공용 금융 구현 상태와 대조해 읽는다.

### 12.3 제9~12시대

- 후속 시대마다 제도 3종·발전 분야·생산 사슬·사건·사회 변화·위험과 대응을 하나의 플레이 루프로 설계한다.
- 공용 금융·교육·GDP·기업·지도·UI 모듈을 확장하고 같은 기능을 시대마다 새로 복사하지 않는다.
- 원자력·정보화·AI·우주 콘텐츠의 상세 기술 목록과 연도별 사건표는 아직 없다. 후보 제도를 구현된 객체처럼 참조하지 않는다.
- 우주 시대의 실제 다행성 지도·성간 이동·우주 함대는 EU5 엔진에서 가능한지 확인되지 않았다. 지구 지도 위의 거점 장부·원정·국제기구 등을 이용한 초기 추상화와 실제 지도 확장을 구분한다.
- 스텔라리스 시점의 인류 문명을 표현하는 것이 장기 목표지만, 기존 시대 뼈대만으로 그 게임의 시스템이 제공되는 것은 아니다.

## 13. 전선 중심 자동전투 — 실현성 검증

특정 제도 수용이나 발전 연구 후 전선 중심 자동전투로 전환하는 아이디어다. 아직 구현된 기능으로 간주하지 않는다.

먼저 확인할 것은 전선 UI, 지역 할당, 군대 명령, 보급, AI 위임, 전쟁·평시 전환에 필요한 스크립트 접근이다. 빅토리아/하츠 오브 아이언식 전선·전투 엔진을 순수 모드로 대체할 수 있다고 전제하지 않는다.

최소 시제품은 한 국가·한 전쟁·제한된 군대로 검증한다. 가능하다면 전략 목표와 지역 할당·명령 보조부터 확장한다. 핵심 제어 기능이 노출되지 않으면 기존 전투 엔진 위의 보조 기능이나 기획 보류로 판정한다.

전환 시 기존 부대·장군·보급·전쟁 상태와 세이브를 보존한다. 시대나 기술 조건을 만족했다는 이유만으로 군대를 일괄 삭제하지 않는다. 이 연구가 금융과 일반 후속 시대 콘텐츠 개발의 선행 조건이 되지 않도록 별도 항목으로 관리한다.

## 14. 장부·성능·AI·세이브의 공통 원칙

### 14.1 회계와 경제 단위

- 지급·투자·배당·구제에는 출처와 받는 주체가 있어야 한다.
- 같은 자산을 native 국고·계층 자금과 모드 준비금에 이중 계상하지 않는다.
- 신용 창출은 통화량을 늘릴 수 있지만 대응하는 자산·부채·준비 규칙을 정의해야 한다. 단순히 모든 돈의 합을 고정하는 방식과 혼동하지 않는다.
- 손실은 주주·채권자·보험자·국고 중 누가 부담하는지 기록한다.
- 화폐 단위 변경과 경제 가치 변화, 실제 회계와 추정 지표를 분리한다.

### 14.2 성능

- 통화는 기준 단위에 대한 환율 하나씩 저장한다. 모든 통화 쌍의 장부를 기본으로 만들지 않는다.
- 통화·은행·기업 계산은 국가/통화별 합산과 월간·분기별 캐시를 우선한다.
- 기존 집계에 새로운 프로빈스·팝 전수조사를 중복 추가하지 않는다.
- 금융 호버와 탭 전환에서 세계 전체를 순회하지 않는다.
- 선택한 대상의 그래프만 표시하고 이력 길이를 제한한다. 장기 게임의 기록을 무한히 누적하지 않는다.
- UI 추가 비용과 시뮬레이션 계산 비용을 분리해 측정한다. 사양에 무관하게 영향이 없다고 보장하지 않는다.
- 같은 세이브·설정에서 월말 처리시간과 구간 진행시간을 비교하고 7시대 이전도 측정한다.

### 14.3 AI와 세이브

- 새 금리·발권·구제·투자 정책에는 AI 규칙도 제공한다. native AI가 새 통화 변수를 자동 이해한다고 가정하지 않는다.
- AI는 가능한 자금과 위험을 확인하고 정책 변경을 너무 자주 반복하지 않는다.
- 기존 기업·주가·본사·채권과 연구 상태를 유지한다. 신규 장부는 모듈 버전으로 한 번만 이행한다.
- 과거 그래프나 기업 수익을 소급해 만들어내지 않는다. 미집계·추정·실측의 상태를 구분한다.
- 새 국가·국가 소멸·태그 변경·통합·분열·정책 전환을 이행 시험에 포함한다.

현재 활성 구성에서 주요 대상은 Glorp, Good Interface, Research Expanded, Economy History, CMF와 TSIN Compat다.

|---|---|
| Glorp | 공유 경제 탭·통계 아이콘·호버·레이아웃 |
| Good Interface | 좌측 패널과 확대/축소 설정 |

현재 최종 경제 GUI에서 `tge_research`와 `ech_` 표시 연결이 확인되지 않았으므로 우선 병합 점검 대상으로 둔다. 기능의 시뮬레이션 코드 존재와 실제 조작 UI 연결을 별도로 확인한다.

Glorp만 원본으로 경제 화면 전체를 재생성하면 다른 경제 UI 모드의 기능을 잃을 수 있다. 로드오더만으로 모든 변경이 자동 병합된다고 가정하지 않는다. 기본 UI용과 로컬 플레이셋용 어댑터를 생성하고 의미 있는 기능을 함께 보존한다.

## 16. 원본 경로와 개발 운영

- 공용 금융·통화·은행·보험·UI 모듈은 기존 전역 경로에 둔다.
- 제7시대 전용 콘텐츠 원본은 `era_7`에 유지한다. 실행용 파일은 manifest의 기존 엔진 경로로 동기화한다.
- 후속 시대 원본 폴더는 실제 콘텐츠 개발 시 같은 모듈 원칙으로 등록한다. 엔진이 최상위 `era_8` 등을 직접 읽는다고 가정하지 않는다.
- 시대 정의와 전역 연결·공용 레지스트리를 무리하게 시대 폴더로 옮기지 않는다.
- 생성 파일은 해당 생성기에서 수정한다. GUI 파일을 만들면 실제 진입·생성 등록·상태 선택·본문 연결까지 확인한다.
- 완료한 논리 단위마다 로컬 커밋한다. 원격 푸시는 사용자가 한다.
- 명확하지 않은 엔진 기능은 작은 실험으로 확인하고, 실현성 검증 결과를 계획에 반영한다.

참고: [era_7 원본 관리](../era_7/README.md), [content_modules.json](../data/content_modules.json).

## 19. 착수 전에 확정할 사항

1. 통화 계층의 첫 범위를 표시 환산에 한정할지, 정책·준비자산까지 함께 도입할지.
2. 기존 `credit` 컨트롤러에서 금융 하위 탭을 안정적으로 운용할 수 있는지.
3. 은행과 기업의 합산 장부에 사용할 수익·자산·부채의 경제 단위와 데이터 출처.
4. native 대출을 어디까지 그대로 사용하고 어떤 계약부터 모드가 책임질지.
5. 준비자산 매입·중앙은행 지원·해외 투자에 사용 가능한 엔진 효과.
6. 연금 수급자와 보험 손실의 실제 데이터 접근 가능 여부 및 추정 방식.
7. 후속 시대의 제도 3종, 제도별 발전 분야, 기존 말기 기술 이행안.

9. HEX를 병용하는 모드와 TSIN 독립 모드의 제공 범위, 국가·시기·효과별 실행 담당. 필수 의존성은 미확정.

12. 역사 사건의 추가대조 자료·실제 바닐라 노출 기준선·지역별 첫 제작분과 팝업 예산.

## 20. 제7시대 역사 사건의 고밀도 확장 — 첫 제작분 부분 구현

### 20.1 범위와 현재 상태

1836~1900년의 실제 역사에서 정치·전쟁·산업·과학·문화·도시생활의 소재를 뽑아 EU5 이벤트·사건열·상황으로 추가한다. 유명 사건뿐 아니라 우표·궁정 일화·신문·교통·발명 시연 같은 작은 소재도 포함한다. 원역사를 그대로 재생하는 선택지만 두지 않고 예방·타협·실패·대체 발전 경로를 설계한다.

현재 시대 레지스트리는 제7시대 1837년 시작, 제8시대 1900년 시작이다. 이번 범위의 1836년 사건은 전환기 도입부, 1900년 사건은 다음 시대 연결로 다룬다. 레지스트리 연도를 바꾸는 요청으로 해석하지 않는다.

역사 검토 초안 당시 제7시대 원본 이벤트는 `era_7/in_game/events`의 27개 파일에 147개 최상위 정의였다. 첫 제작분 24개 추가 후에는 28개 파일·171개 정의다. 전역 시스템 이벤트를 포함한 전체 수와 혼동하지 않는다. 기존 상황 8종과 일반형 사건을 먼저 재사용한다. 민족의 봄·통일·개항·근대화·기근·콜레라·장기불황·노동·금광·발명 소재를 중복 생성하지 않는다.

### 20.2 목표 밀도와 노출

| 항목 | 초기 설계 목표와 제한 |
|---|---|
| 최종 이벤트 정의 | 중복 정리 후 약 800~1,200개 후보. 수량 자체를 완료 기준으로 삼지 않음 |
| 사건열 | 소사건 1~3개, 중간 사건 4~8개, 대형 사건 10~25개 |
| 상황 | 기존 8종을 포함한 약 20~30종 검토; 한 국가의 주요 동시 참여는 보통 2~4개 |
| 선택 팝업 | 평시 연 4~6개, 고밀도 설정 연 8~12개를 시험값으로 사용 |
| 짧은 소식 | 연 8~16건을 시험값으로 사용; 모두 강제 팝업으로 만들지 않음 |
| 바닐라 대비 | 동일 속도·유사 국가 규모에서 실제 진행시간당 의미 있는 선택·새 소식을 측정하고 3~5배 수준까지 조정하는 목표 |

바닐라의 실제 국가별 노출량은 아직 측정하지 않았다. 위 수치는 목표이며 검증된 배율이 아니다. 많은 사건이 있어도 특정 국가에 적합한 후보가 적으면 체감 밀도가 낮으므로 비유럽 산업국·소국·비산업국별 노출을 함께 측정한다.

기존 `tsin_flavor_events_per_year`는 기본 3·낮음 1·높음 5·끔 0이며 여러 사건군이 예산을 공유한다. 모든 이벤트가 이 예산을 쓰는 것은 아니다. 사용처를 조사한 뒤 주요 역사 사건·필수 상황 후속·산업사회·생활사·해외 소식의 우선순위를 관리한다. 종료와 필수 대응을 풍미 예산으로 봉쇄하지 않는다. 같은 날 몰림·주제 반복·동일 시설의 이중 완공을 방지한다.

### 20.3 역사적 배경과 대체 역사의 연결

- 국가·인물·지역·제도가 존재하면 역사 특정형을 사용한다. 다른 소유국이 같은 지역과 조건을 보유하면 지역사 버전을 사용한다.
- 크게 달라진 세계에는 조건 기반 일반형을 제공한다. 역사 국가가 형성되지 않아도 산업·교육·과학·노동·생활사 콘텐츠가 전부 사라지지 않게 한다.
- 전쟁·기근·불황은 연도만으로 강제 발생시키지 않는다. 실제 원인과 예방 투자를 읽는다. 국가 형성을 보장하는 제21절과 비극을 강제 재현하는 기능을 구분한다.
- 1848년 사상 출판·노동자 조직·지역 코뮌은 기존 운동 변수로 다룬다. 제8시대 정당·이념 체계 전체를 선행 구현할 필요는 없다.
- 1900년을 넘는 전쟁·위기는 상태를 다음 시대로 계승한다. 1901년 연방 성립·1906년 복권·하버-보슈 공정을 제7시대의 확정 결말로 넣지 않는다.
- 작은 사건은 인물·현지 효과·관계·작은 비용 중심으로 만든다. 영구 전국 보너스를 수백 개 누적시키지 않는다.

### 20.4 기존 상황 확장과 신규 상황 후보

기존 `tsin_springtime_of_nations`, `tsin_national_unification`, `tsin_defensive_modernization`, `tsin_long_depression`, `tsin_grain_invasion`, `tsin_great_migration`, `tsin_scramble_for_colonies`, `tsin_world_exhibition`을 먼저 확장한다.

신규 후보는 전신망·철도 국가사업·도시 위생·식민지 통치권·인도형 대봉기·내전 후 재건·완충국 보호권 경쟁·의화단형 국제 위기·전기 공급권 등이다. 장기 진척·참여국·복수 행동·종료가 없는 소재는 독립 상황 대신 사건열로 만든다. 갑오·광무형 개혁은 기존 근대화 상황의 지역형부터 검토한다. 상황별 주요 행동·진척·참가자·종료 UI가 실제로 연결되어야 한다.

### 20.6 역사 소재·파생 사건 후보 180개

2026-11-15의 별도 역사 검토안을 통합했다. 각 행은 최종 이벤트 정의 하나가 아니라 집필 소재다. 동일한 역사 사건에서 파생한 후속·일반형도 있어 독립적인 역사 사건이 정확히 180개라는 뜻은 아니다. 자료 링크가 붙은 행은 132개, 나머지 48개는 추가대조 후보다. 링크가 있는 행에도 세부 추가대조 표시는 남긴다. 조건·선택·효과는 역사 자료의 결론이 아닌 게임화 제안이다. **확장**은 기존 일반형·유사 소재와 연결할 대상, **신규**는 현재 조사에서 직접 대응을 확인하지 못한 후보다. 활성 모드 전체의 최종 중복 검사는 별도다. ## 21. 역사 진행·럭키네이션 — 러시아 시제품 부분 구현

### 21.1 목표와 우선순위

주요 AI 국가가 역사 콘텐츠의 배경을 만들도록 성립·통합·확장·승계·쇠퇴를 단계적으로 관리한다. 러시아·청·무굴부터 시제품을 만들고 독일·이탈리아·식민 국가로 확장한다. 무굴의 형성만 보장하고 1900년까지 무조건 보호하는 식의 영구 특혜는 목표가 아니다.

단계는 **정상 유도 → 형성 지연 감지 → 1차 지원 → 2차 지원 → 대체 AI 주도국 선정 → 조건부 강제 형성 → 비상 지원 종료**다. 연도·유예기간·버프 수치는 미확정이며 장기 진행으로 조정한다. AI 지원 체계는 앞시대부터 필요하므로 공용 모듈로 둔다. 제7시대 전용 지역 사건과 설명만 `era_7` 원본으로 관리한다.

### 21.2 플레이어의 핵심 영토 보호 — 필수 요구

**형성에 필요한 핵심 지점 중 하나라도 플레이어 소유이면 해당 역사 국가의 강제 형성 전체를 실행하지 않는다.** 그 지점을 제외한 별도 우회 형성으로 요구를 회피하지 않는다. 시작 검사와 실행 직전에 다시 검사하고, 이벤트 지연 중 소유권 변경·플레이어 국가 변경·멀티플레이 참가도 고려한다.

권장 추가 보호는 플레이어의 모든 하위 종속국·플레이어가 점령한 핵심 지점·관련 전쟁의 진행 중 결과다. 직접 종주국 한 단계 검사만으로 중첩 종속 관계까지 보호됐다고 간주하지 않는다. 점령·관련 전쟁은 종료 뒤 재검사한다. 자연적인 AI 정복과 엔진의 정상 국가 형성을 무조건 금지하는 규칙과도 구분한다.

현재 바닐라 `RUS_f`의 명시적 필수 도시는 모스크바·노브고로드·트베리·블라디미르이며, 상트페테르부르크는 이 목록에 없다. 문화·독립·수도·영토 비율 등의 조건도 있다. 실제 활성 플레이셋의 정의를 기준으로 보호 집합과 최소 필요 영토를 만든다. 역사적 희망 영토 전체를 필수 핵심 지점으로 간주하지 않는다.

### 21.3 지원·대체 세력·형성

- 럭키네이션 지원은 초기에 경제·행정·인력 회복, 필요 시 지역 통합을 위한 군사·병참으로 확대한다. 실제 수치는 미확정이다.

|---|---|---|
| 앞시대 역사 목표·국가 계보 | HEX 기존 경로 | 역할 읽기/매핑 계약과 갱신 호환 |
| 러시아·청 등의 기존 형성·승계 | 해당 국가·기간의 관리자를 하나로 지정 | 핵심 지점 보호 강화, 멸망/기한 이후 복구, 성공 상태와 지원 종료 |
| 럭키네이션 보정 | HEX+TSIN 합산 상한·공동 상태로 관리 | 단계·실패 감지·대체 주도국·차단 사유 |
| 1836~1900 이후 역사 권역 | 검토 후 TSIN/호환 계층 | 1836·1850·1870·1900 등의 자료 기반 단계; 아직 영토표 미작성 |
| 월경지 유상 매각 | TSIN | 전략 가치·구매국·결제·정리; HEX가 즉시 되돌리거나 청구하지 않게 예외 연동 |
| 역사 사건·상황 | TSIN 기존 콘텐츠와 연결 | 중복 발생 방지·형성/승계/전쟁 결과 전달 |

별도 이름으로 스크립트를 추가해도 기존 HEX 연간 훅은 계속 실행된다. 런처에서 뒤에 두는 것만으로 두 관리자가 분리되지는 않는다. 시제품에서 국가·효과별 실행 담당을 정하고, 호환 계층에서 필요한 정의/호출만 선택적으로 조정해야 한다. 매각 영토는 영구적으로 역사에서 삭제하기보다 거래 표식·인정 기간·청구 재개 정책을 공유한다. 전후 처리·역사적 강제 승계·매각이 같은 영토에 겹치면 실행 순서를 명시한다.

설치본은 `tools/build.py`, `src/data/*.json`에서 생성했다고 주석에 적지만 해당 원본·생성기는 이 구독 폴더 목록에 없다. 구독 경로의 수 MB 생성 파일을 수작업으로 복제·누적 편집하는 대신 자료와 상태 기계로 관리한다. 제안 원본은 `data/historical_progression.json`, `data/lucky_nations.json`, `data/border_trade_rules.json` 등이며 **현재 존재하는 파일이 아니라 추후 설계 후보**다. 엔진 경로 생성·ID/지점 검증·기본/호환 실행 모드를 한 생성 계약으로 관리한다.

### 23.4 구현 순서·완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| H0 | HEX 활성/비활성·충돌 정의·플레이어 보호·변경 없는 국경 진단 | 효과별 담당표·재현 세이브·오판 목록·연산 기준선 |
| H1 | 러시아 한 국가의 럭키네이션 시제품 | 정상 형성·지연·멸망·대체 후보·1700년 이후·플레이어 핵심 도시 보유·중첩 종속국·실행 직전 변경 시험 |
| H2 | 작은 내륙 월경지의 AI 매각 | 중요 거점 보유·실제 결제·구매자 없음·가격 거절·왕복 방지·HEX와 소유권 충돌 없음 |
| H3 | 청·무굴·국경 돌출부·후속 역사 권역 | 문화/정부/천명/상황 승계·쇠퇴·연속성·통계 갱신·성능 확인 |
| E0 | 역사 사건 후보·기존 이벤트·상황·HEX 사건 매핑 | 중복과 자료 추가대조 목록·지역/일반형·발동/종료 계약 |
| E1 | 일반형 사건 첫 제작분과 지역사 순차 추가 | 실제 노출 밀도·부적합 사건·위기 예방·팝업·효과 누적·상황 UI 검증 |

H0 뒤에 E0와 H1을 진행할 수 있다. 모든 경제 장부가 끝날 때까지 역사 콘텐츠를 막지 않는다. 금융 장부가 필요한 사건 분기만 해당 경제 단계에 의존시킨다. 기존 M0~M7은 경제·후속 시대 순서로 유지하며, 이 역사 작업은 별도 트랙이다. 제13절의 전선 자동전투 보류를 해제하는 요청으로 해석하지 않는다.

인게임 시험은 HEX 켬/끔, TSIN 단독/전체 플레이셋, 인간의 러시아 핵심 도시 보유, 멀티플레이 인간 국가, 플레이어 하위 종속국, 정상/패전/내전/국가 소멸, 저장/로드, 1837·1900년 전환을 포함한다. 로그에는 지원 단계·형성 차단 이유·영토 거래·청구·실행 담당을 남겨 두 모드의 재이전과 중복 호출을 확인한다. 이 절은 초안의 목표 범위다. 이후 P1~P4 코드 구현 상태는 실행 기록에서 확인한다. 러시아 시제품·진단·역사 첫 제작분을 실제 매각·청/무굴·전체 역사 사건의 완료로 해석하지 않는다.
