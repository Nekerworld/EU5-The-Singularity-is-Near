# TSIN civilization dashboard — extensible UI contract

## Frontends and entry points

`in_game/gui/tsin_dashboard.gui` creates the standalone, movable bottom-left dock and the movable 900x660 management window. It does not require Cheat Menu Pro, Glorp, CMF or any other UI mod. The dock has an expandable set of six shortcuts. Opening a shortcut selects the matching tab of the same window; closing only changes local UI variables. The independent-button/window/state pattern follows the installed Cheat Menu Pro implementation, using native GUI types and no copied cheat assets or gameplay effects.

Stable top-level domains are national statistics, economy, population/society, companies/finance, crises/policies and science/technology. Later eras extend modules inside these domains. The top-level limit of six is an explicit layout constraint; adding more domains requires a layout change rather than silently overflowing the screen.

The optional Glorp frontend is a thin adapter to `tsin_ui_compact_strip`. Both frontends use the same generated metric definitions, country cache readers, missing-value handling and K/M/B/T formatters. No Glorp types or assets are referenced by the standalone frontend. Local-only workshop overrides remain generated by gen_glorp_stats_compat.py.

## Source and generation

Edit `ui/dashboard_registry.json`, then run:

```powershell
python -B tools/gen_dashboard.py
python -B tools/gen_dashboard.py --check
python -B tools/validate.py
python -B tools/tests/test_dashboard.py
```

Generated files are marked. The registry declares stable IDs, localized names/help, units, update frequency, tab membership, country variable sources, cheap status predicates, native-view/map shortcuts and history providers. The generator rejects duplicate IDs, missing localization, invalid units/frequencies and missing tab references. The build uses native templates; no runtime Python process is required.

## Data contract and costs

35 metrics currently read cached country variables. The shared UI never traverses countries or locations or recomputes GDP. Monthly/quarterly/event values retain their actual provider cadence. Company totals are annual snapshots; stock prices continue to use their quarterly provider. Missing/uninitialized metrics show an em dash, not a fabricated zero. Cached population and factory jobs follow EU5/TSIN population units (thousands); GDP per population unit retains the existing formula.

`tsin_dashboard_update_effect` runs after the existing annual aggregate has updated education and GDP. It stamps the aggregate year, caches population and calls registered era-module annual effects. The industrialization provider caches company count/limit/value without adding a location scan. The dashboard does not claim to display a per-good shortage diagnosis: market inspection remains in the native economy view.

The GDP history provider remains `tsin_record_gdp_history_effect`, preserving existing ten-sample save variables and same-year replacement behavior. The generic history renderer takes prefix, year prefix, peak variable, sample count and provider effect from the registry. Registering another history does not magically collect data: its era module must supply and schedule the recorder. Do not use historical values from a different calculation formula as if directly comparable; version the provider and implement an explicit migration or begin a separately labeled series.

## Save compatibility and migration

The registry schema_version produces `tsin_dashboard_data_version` migration metadata. Existing saves receive the metadata on a lightweight monthly pulse once GDP exists. The module bootstrap seeds cheap current company/population caches once; it does not invent a past aggregate date. No old variables are removed and no past observations are fabricated. Annual statistics obtain a real `tsin_statistics_year` only when the aggregate runs; until then the UI explicitly says the year has not been recorded. Industrialization calculation metadata is separately stamped as `tsin_industrialization_statistics_version`.

Modules may provide `annual_effect`, `update_trigger` and `migration_effect`. Migration runs only for an older framework data version; it must be idempotent, and must inspect its own previous module version. Future-version saves are not downgraded. A schema version bump alone must not be used to wipe country data. Gameplay effects belong in module files; generated shared GUI predicates are read-only.

## Adding Age 8 and later

1. Add an era module with globally unique IDs to the registry; keep existing IDs stable.
2. Supply metrics as cached country variables, specify their true units/frequency, and attach them to existing domains.
3. Provide module calculation/migration effects, checking their own version and unlock conditions. Later eras should retain existing GDP/education sources unless a formula migration is deliberate.
4. Add institutions, crisis predicates, links and optional history providers. Unknown future-age IDs must not be referenced until those game objects exist.
5. Regenerate, check reproducibility, validate references and run boundary tests. Check layout, hover, scroll, close/open and native navigation in game.

## Current behavior and limits

The first version provides 35 metrics, 16 state cards and 10 native-view/map links. Four TSIN disasters and eight world situations are identified as such; a world-active state does not imply country participation. Institutions show whether the embrace requirement is met. Existing legislation, company founding and costs remain in their original interfaces. The read-only dashboard does not enact policies or manufacture resources.

GUI state uses `GetVariableSystem` names under tsin_ui_; it does not write gameplay state when a window is opened. Dragging uses the native movable window behavior; automatic layout/position persistence across a game restart is not promised. Actual GUI appearance and script-glue behavior require a restarted in-game test; static success is not proof of runtime layout.
